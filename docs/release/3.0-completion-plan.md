# 3.0 completion plan

**Created:** 2026-10-18. This plan supersedes the open-ended gate in `coordinator.md` /
`readiness.md` for deciding when 3.0 ships. There is no deadline; the goal is a release
that is correct, verified in the real app, and understandable to photographers.

## Scope decisions (owner-approved 2026-10-18)

- **Keep, and qualify fully:** Whisper transcription of camera voice-memo WAV sidecars
  (Caption single-photo, Browser batch, Settings → Transcription model management, use
  through `{voiceMemoTranscript}`).
- **Cut back:** MCP automation ships as an *experimental* feature limited to read-only
  inspection and previews. No new admission/receipt/epoch/journal machinery for 3.0.
  Execution tools that are unfinished (template apply, IPTC commit, start face scan,
  Develop batch execution via MCP) move to 3.1. Existing code is frozen, not deleted,
  unless it is dead.
- **Whisper model distribution:** ship the pinned, SHA-256-verified download path. The
  signed catalog / replay-ledger lifecycle is not a 3.0 requirement.
- **Already deferred:** Deadline Workspace, multi-lens faces, AI-origin detector.

## Phase 1 — correctness bugs in core workflows

1. Paste IPTC onto RAW silently does nothing (only C2PA got a sidecar). Route every file
   through `MetadataWriteMode.current(forC2PA:isRaw:)`.
2. Import template metadata onto RAW: verify, and route through a sidecar if skipped.
3. Develop multi-image paste: RAW skipped while marked edited; stale sidecar crs can win.
4. Make "skipped RAW" visible to callers of `SwiftExifWriteEngine.writeFields` instead of
   a log-only success.
5. Save As collision default `.replaceExisting` can overwrite a RAW+JPEG pair partner when
   exporting to the source folder → default to appending a number.
6. FTP upload swallows metadata / Develop read failures (`try?`) → surface them.
7. Fire-and-forget fallback sidecar write in `MetadataViewModel` reports success early.
8. Delete unused sidecar writers that would drop crs if ever called
   (`saveSidecar`, `saveCameraRawOnly`, `stripIPTCFromSidecar`,
   `syncCameraRawToXMPSidecar`) after confirming no callers.

Each fix gets a focused regression test.

## Phase 2 — scope cut

1. MCP: disable/hide unfinished execution tools; label Automation as experimental; move
   recovery/review/history screens behind an Advanced disclosure.
2. Freeze the signed Whisper distribution code out of the release path (or remove if
   unused in production).
3. Decouple the native WAV transcription path from MCP admission machinery where the
   coupling adds failure modes without user value.

## Phase 3 — WAV transcription qualification

1. Real end-to-end inference with the bundled FFmpeg+Whisper on real camera WAVs
   (Sony), CPU and GPU, Norwegian and English, at least Base and Turbo models.
2. Cancellation, offline use, missing/removed model, corrupt WAV, moved/renamed pairs.
3. Caption single photo, Browser batch, `{voiceMemoTranscript}` into Description.
4. Apple on-device speech: permission string / prompt behaviour on a clean account.

## Phase 4 — platform and packaging

1. Location entitlement under hardened runtime (`com.apple.security.personal-information.location`).
2. Description Assistant default provider falls back to local when Foundation Models is
   unavailable (macOS 26).
3. Version `3.0.0`, build ≥ 743; `## 3.0.0` changelog section with Highlights.
4. Publish FFmpeg and gallery-dl corresponding source (GPL) and link it.
5. Consider `sparkle:minimumAutoupdateVersion` / explicit major-upgrade notes.

## Phase 5 — user-facing docs

1. 3.0.0 release notes: 10–15 plain-language bullets for 2.x users, plus backup and
   mixed-version iCloud Known People note.
2. Rewrite `docs/limitations-3.0.md` to 1–2 readable pages.
3. Trim README; move MCP internals to a developer doc.
4. Regenerate the manual testing checklist for what is actually in 3.0 (remove Deadline,
   add watermark layer, web import, shortcut editor, Settings search, transcription).

## Phase 6 — verification and release candidate

1. Full unit test suite from a checkout with the AuraFace model provisioned.
2. Agent-driven app checks where computer use is available.
3. Owner hands-on pass with the checklist on a notarized candidate, especially: watermark
   layer, RAW metadata flows, export, FTP, transcription.
4. Fix findings, then release.
