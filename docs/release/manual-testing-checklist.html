How to use this document

  1. The coordinator records the candidate identity, fixture inventory, approved scope and evidence links. Work only on disposable copies in an isolated profile; preserve originals and existing user settings.
  2. Run the agent computer-use cases through the actual application and capture dated observations. Unit tests or source inspection cannot substitute for visual interaction. Record the executing agent or tester and tool/version in notes.
  3. Complete the external / hardware prerequisites with the required samples, endpoints, reviewers and devices. An unavailable prerequisite is blocked, never automatically waived. Record any explicit scope decision and its owner.
  4. Once the coordinator has verified the candidate and accounted for every mandatory gate, hand the user this candidate and the final user acceptance cases. Agent observations never count as the user’s acceptance.
  5. For each result, include actual outcome, evidence location, fixture ID, environment and defect reference. Fail and blocked need a reason. Pass requires observed evidence. Revalidate affected cases after fixes; a new candidate identity marks old observations stale.

Priority: P0 protects data, release trust or the core workflow. P1 is still a required quality gate. This is a starting test inventory, not a replacement for the plans; add cases when implementation or scope changes.
