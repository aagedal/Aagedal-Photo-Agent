# IPTC 2025.1 editorial support matrix

This is the implementation ledger for Photo Agent's first journalistic metadata milestone. It is
based on IPTC Photo Metadata Standard 2025.1 and must be updated in the same change that adds or
removes support.

For the generated app-level registry of stable field IDs, writer keys, normalized read-back rules,
and current delivery-carrier boundaries, see [Metadata field and delivery support](metadata-field-support.md).
That generated table describes implementation coverage; this standards ledger remains the source for
XMP/IIM mapping status and outstanding external interoperability evidence.

## Status legend

- **Supported:** modeled, read, written, and exposed by the current app; fixture evidence is still
  required before a public interoperability guarantee.
- **Partial:** present, but cardinality, mapping, precision, conflict behavior, or UI is incomplete.
- **Planned:** selected for the first editorial field set but not implemented end to end.
- **Preserve:** not editable yet; reads and unrelated writes must retain the original value.
- **Deferred:** outside the first editorial UI milestone.

`IIM` values use record:dataset notation. A dash means the field has no IPTC-IIM equivalent.

`minorHumanEdits`, `softwareImage`, and `digitalArt` are not offered by the picker.

## Preservation-only specialist groups

Until intentionally modeled, the metadata engine must preserve fields in these groups:

- Artwork or Object, Product, Registry Entry, Licensor, Image Creator, and Copyright Owner.
- Model and Property Release identifiers/status.
- Location structures beyond the selected editorial location fields.
- Embedded Encoded Rights Expression and linked rights-expression fields.
- Any unknown namespace and unknown property within a known namespace.

## Evidence still required

- Confirmed-redistributable IPTC 2025.1 reference image, decodable HEIC/HEIF, and representative
  camera RAW original. The committed CC0 corpus already covers TIFF, PNG, JPEG XL, and the authentic
  RAW/XMP-sidecar safety boundary.
- Extend the generated per-container read/write/preserve report to the remaining licensed fixtures.
- Adobe Bridge and Photo Mechanic read/write/read notes for exposed editorial fields.
- IPTC reference-tool validation included in release testing.

Completed locally: a CC0 complex XMP fixture, generated no-metadata JPEG, conflicting XMP/IIM
adapter case, semantic no-op snapshot, unrelated-caption preservation test, embedded-JPEG
foreign-property preservation test, generated maximum-IIM-byte/timezone-precision corpus, and
structured creator-contact/location sidecar and embedded-JPEG round trips with unknown-member
preservation. Description Writer and Creator Job Title additionally round-trip through scalar
Photoshop XMP and IPTC-IIM in sidecars, embedded JPEGs, templates, rendered exports, and clears.
Country Code stores canonical uppercase alpha-3 values independently of localized picker labels,
validates against all 249 current ISO 3166-1 assignments, and round-trips through
`Iptc4xmpCore:CountryCode` and IIM 2:100 with XMP precedence and authoritative clears.
Organisation Shown Name and Code preserve ordered, deduplicated values as independent IPTC
Extension bags; both fields round-trip through JSON, XMP sidecars, embedded JPEGs, templates,
imports, batch edits, rendered exports, and authoritative clears. The CC0 preservation fixture
contains multiple values for both properties. Rights Usage Terms and Web Statement of Rights now
round-trip as `xmpRights:UsageTerms` and `xmpRights:WebStatement`, participate in the same editing,
template, import, batch, export, and clear paths, and validate non-empty web statements as HTTP(S)
URLs. The string model currently exposes the XMP `x-default` usage term; preserving and editing
additional language alternatives remains open.
Urgency is stored as an integer independently of its explanatory picker labels; bounded 1–8
pickers are available in metadata editing, import, and templates. Sidecar and embedded JPEG writes
dual-write `photoshop:Urgency` and IIM 2:10, reads prefer XMP and fall back to IIM, authoritative
clears remove both representations, and the default validation profile blocks values outside 1–8.
Scene Codes use a frozen 24-entry IPTC Scene NewsCodes snapshot and canonical six-digit storage.
Metadata editing presents human-readable type-ahead labels; common Scene URI and `scn:` aliases
normalize at the model boundary, while unknown incoming values remain visible and survive unrelated
edits until validation is resolved. Ordered, deduplicated values flow through JSON, history, batch
editing, import, templates, variables, browser search, rendered export, and delivery preparation.
Sidecar and embedded JPEG writes use an `Iptc4xmpCore:Scene` XMP bag with authoritative clear
behavior.
Digital Image GUID is stored independently from filenames and other supplier identifiers. Existing
values are preserved across unrelated edits; only an explicit editor, template, import, batch, or
history action can replace or clear the value. Empty records remain empty—ordinary metadata edits
never synthesize or rotate an identifier. Sidecar and embedded JPEG writes use
`Iptc4xmpExt:DigImageGUID`, and focused tests cover explicit clear plus unrelated-caption
preservation.
Image Supplier Image ID remains independent from Digital Image GUID, Job ID, filenames, and the
structured Image Supplier identity. Agency-specific text values flow through JSON,
history, batch editing, import, templates, variables, browser search, rendered export, and delivery
preparation. New XMP sidecars and embedded JPEGs use canonical `plus:ImageSupplierImageID`; reads
also accept the namespace spelling emitted by earlier Photo Agent builds so existing files migrate
without data loss. Structured suppliers use an ordered `plus:ImageSupplier` sequence with PLUS
identifier/name children, explicit append/replace/clear operations, and semantic read-back.

Subject Codes now retain their legacy eight-digit/IIM representation with URI/QCode read aliases,
while new Media Topic and Genre values use typed CV-Term structures carrying vocabulary, term,
name, and optional refined-about identifiers. Genre is intentionally separate from the legacy
scalar Intellectual Genre, as required by IPTC 2025.1. Unknown controlled terms remain visible and
preserved. The structured Image Supplier and controlled-field implementation compiled with the full
app/test target and passed 51 focused model, mutation, parser, XMP, and verification tests.

Creator now uses an ordered sequence as its source of truth. Legacy scalar JSON and APIs remain a
first-item compatibility boundary, while current JSON, `dc:creator` RDF sequences, repeatable IIM
By-line datasets, templates, imports, history, batch operations, variables, and semantic read-back
retain every creator in order. Date Created has a validated typed projection that preserves the
exact lexical value, represented precision, fractional digits, and known/unknown timezone state;
IIM receives only losslessly representable date/time components while XMP remains authoritative.
The integrated Creator/Date validation passed 211 focused tests across 19 suites, including an
embedded-JPEG round trip.

The remaining localized-text limitation is a carrier dependency, not a UI-label ambiguity:
SwiftExif 1.9.10 exposes `rdf:Alt` as one `x-default` string and discards the other language entries.
Headline and localized Title now have independent write carriers: changing or clearing Headline
does not create, replace, or remove `dc:title` or IIM Object Name. The shipped scalar read fallback
remains for compatibility, and non-default alternatives for Title, Description, Copyright, Rights
Usage Terms, and accessibility descriptions still cannot be claimed as losslessly editable. That
boundary needs an upstream multi-language XMP value or a deliberately maintained local fork before
the matrix can mark those rows complete.
