# IPTC 2025.1 editorial support matrix

This is the implementation ledger for Photo Agent's first journalistic metadata milestone. It is
based on IPTC Photo Metadata Standard 2025.1 and must be updated in the same change that adds or
removes support.

## Status legend

- **Supported:** modeled, read, written, and exposed by the current app; fixture evidence is still
  required before a public interoperability guarantee.
- **Partial:** present, but cardinality, mapping, precision, conflict behavior, or UI is incomplete.
- **Planned:** selected for the first editorial field set but not implemented end to end.
- **Preserve:** not editable yet; reads and unrelated writes must retain the original value.
- **Deferred:** outside the first editorial UI milestone.

`IIM` values use record:dataset notation. A dash means the field has no IPTC-IIM equivalent.

| `algorithmicallyEnhanced` | Algorithmically Altered |
| `digitalCreation` | Digital Creation |
| `dataDrivenMedia` | Data-Driven Media |
| `trainedAlgorithmicMedia` | Created Using Generative AI |
| `algorithmicMedia` | Pure Algorithmic Media |

| `composite` | Composite (Unspecified Elements) |
| `compositeCapture` | Composite (Capture) |

New writes use `http://cv.iptc.org/newscodes/digitalsourcetype/{identifier}`. Reads also accept
HTTPS, `digsrctype:` QCodes, and the legacy short token. Retired concepts such as
`minorHumanEdits`, `softwareImage`, and `digitalArt` are not offered by the picker.

## Preservation-only specialist groups

Until intentionally modeled, the metadata engine must preserve fields in these groups:

- Artwork or Object, Product, Registry Entry, Licensor, Image Creator, and Copyright Owner.
- Model and Property Release identifiers/status.
- Location structures beyond the selected editorial location fields.
- Embedded Encoded Rights Expression and linked rights-expression fields.
- Any unknown namespace and unknown property within a known namespace.

preservation. Description Writer and Creator Job Title additionally round-trip through scalar
Photoshop XMP and IPTC-IIM in sidecars, embedded JPEGs, templates, rendered exports, and clears.
Country Code stores canonical uppercase alpha-3 values independently of localized picker labels,
validates against all 249 current ISO 3166-1 assignments, and round-trips through
`Iptc4xmpCore:CountryCode` and IIM 2:100 with XMP precedence and authoritative clears.
Organisation Shown Name and Code preserve ordered, deduplicated values as independent IPTC
Extension bags; both fields round-trip through JSON, XMP sidecars, embedded JPEGs, templates,
imports, batch edits, rendered exports, and authoritative clears. The CC0 preservation fixture
contains multiple values for both properties. Rights Usage Terms and Web Statement of Rights now
round-trip as `xmpRights:UsageTerms` and `xmpRights:WebStatement`, participate in the same editing,
template, import, batch, export, and clear paths, and validate non-empty web statements as HTTP(S)
URLs. The string model currently exposes the XMP `x-default` usage term; preserving and editing
additional language alternatives remains open.
Urgency is stored as an integer independently of its explanatory picker labels; bounded 1–8
pickers are available in metadata editing, import, and templates. Sidecar and embedded JPEG writes
dual-write `photoshop:Urgency` and IIM 2:10, reads prefer XMP and fall back to IIM, authoritative
clears remove both representations, and the default validation profile blocks values outside 1–8.
Scene Codes use a frozen 24-entry IPTC Scene NewsCodes snapshot and canonical six-digit storage.
Metadata editing presents human-readable type-ahead labels; common Scene URI and `scn:` aliases
normalize at the model boundary, while unknown incoming values remain visible and survive unrelated
edits until validation is resolved. Ordered, deduplicated values flow through JSON, history, batch
editing, import, templates, variables, browser search, rendered export, and delivery preparation.
Sidecar and embedded JPEG writes use an `Iptc4xmpCore:Scene` XMP bag with authoritative clear
behavior.
