A · Mask reopen fix — closes issue 1 if all pass

1.Mask survives close + reopen
Create a radial mask in the edit view — move it off-center, stretch it, rotate it. Close the edit view, reopen.
Expect: identical geometry — not a generic centered ellipse.
2.Fast close + reopen (race probe)
Same as #1, but close and reopen as quickly as possible. Probes the async-write race (metadataWriteTask) the handoff doc suspected — unit tests can't rule this out.
Expect: geometry still correct.
3.Mask + crop + rotation together
Repeat #1 on an image that also has a crop and straighten angle — they share the crs block.
Expect: mask, crop, and angle all survive reopen.

B · Mask slider persistence — closes issue 2 if it passes

4.Mask exposure + contrast persist to XMP and back
Set exposure and contrast on a mask, save, dump the XMP. Then reopen the edit view.
Expect: non-zero crs:LocalExposure2012 / crs:LocalContrast2012 inside the correction; global crs:Exposure2012 has not absorbed the mask exposure; sliders show your values on reopen.
If it fails: write-side bug — start at the mask-slider bindings, EditWorkspaceView ~2790.

C · crs block replacement — confirms issue 4's implementation

5.Develop save drops ACR-only settings intentional change
Take a JPEG edited in ACR with settings the app doesn't model (Texture, vignette, HSL). Make any develop edit in the app, save, dump XMP. Then open in ACR.
Expect: ACR-only props gone; our settings present; crs:AlreadyApplied="False" and crs:CompatibleVersion present; ACR preview matches our render (no double-processing).
6.Caption-only save preserves ACR settings fixed — re-test
Same kind of file, but only edit the caption — never open the edit view — and save.
Expect: ACR settings survive. FAILED on first pass (every save rewrote the crs block); fixed 2026-06-12 — saves now skip the crs block entirely unless develop settings actually changed vs the loaded baseline.
7.Develop reset wipes the whole block
Run a develop reset on an ACR-edited image, dump XMP.
Expect: crs block essentially empty — no masks, no tone curve, no ACR leftovers.
8.Paste develop settings — masks & tone curve fixed — re-test
Cmd+C on an image WITH masks, Cmd+V onto one and several targets. Then also paste from a mask-LESS source onto a target that has masks.
Expect: pasting from a masked source lands the masks (and tone curve) on the targets; pasting from a mask-less source leaves the targets' masks alone (merge-style). Originally paste dropped masks/tone curve entirely; fixed 2026-06-12.
9.Exports carry zero crs
Export/render an image whose source had ACR settings, dump the exported file's XMP.
Expect: zero crs: properties in the export.

D · Bridge / ACR regression checks

10.Bridge badges app-edited files
Check both a file with masks and one with only global develop edits — the no-mask case is newly stamped with AlreadyApplied="False".
Expect: edited badge on both.
11.App-made mask renders correctly in ACR 18.3.2
Open one app-made mask in ACR.
Expect: same position, same strength.

E · Known-broken — confirm scope only (open issues 3 & 5)

13.Mask misplaced on orientation ≠ 1 expected failure
Mask on an image with EXIF orientation ≠ 1 — no orientation transform yet (issue 5).

F · Rotation fixes — added 2026-06-12 after your mid-testing report

14.Edit view after browser rotation (the reported bug)
Rotate a 3:2 image 90° in the thumbnail view, open the edit view.
Expect: correctly rotated, no stretch — surface and pixels agree. Test both a C2PA file (file's EXIF flag never updates — the persistent case you hit) and a plain JPEG opened immediately after rotating (the race case).
15.Spacebar preview after rotation
Rotate in thumbnail view, then hit space — including on an image you previewed BEFORE rotating (that's the stale-cache case).
Expect: preview shows the new orientation.
16.Rotated RAW via neighbor precache
Rotate a RAW in the browser, open its NEIGHBOR in the edit view, then navigate to the rotated RAW (it arrives via the precached texture).
Expect: correct orientation.
17.Scopes + before-toggle on a rotated image
On a rotated image in the edit view: check the waveform scope and the before/after toggle (both read the now-corrected source image).
Expect: both show the rotated frame, before-toggle doesn't snap back to unrotated.
